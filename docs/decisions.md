# Naming decisions

This file records what the toolkit does when established conventions disagree. Each entry is binding for corpus cases. If a case contradicts an entry, the case is rewritten to match the entry. IDs are stable.

## Movies

- **M1 Folder ownership.** A folder owns a video when the folder carries a provider ID, a year, or a title that is a prefix of the video's title. Otherwise the video is a movie of its own. A same-named wrapper (`Alien (1979)/Alien (1979)/`) collapses into one folder. A video is ambiguous when its own title or year contradicts a trusted owning folder. Only a trusted file name (M2) can contradict the folder. Two titles agree only when their comparison words are equal (P4: case, punctuation, accents, a leading article, and numbers written as Roman numerals I-XX or spelled one-twenty are folded): `vs.` equals `vs`, `The Northern Passage` equals `Northern Passage`, `Northern Passage II` equals `Northern Passage 2`. Before the comparison, the edition words and phrases at the end of the file's title are dropped (data, M9: `Super-Sized`, `R-Rated Version`, `Extended Edition`, `Director's Cut`). A short alias at the start of either title is also dropped: an all-caps acronym of two to four letters before the full title (`AVP Alien vs. Predator` agrees with `Alien vs. Predator`). Any other difference is a contradiction (`Green Lantern` against `Green Lantern Emerald Knights`). A provider ID on the owning folder fixes the identity. A video's differing title, year or episode token is then an alternate name and not a contradiction. A different ID of the same provider is still a contradiction (M8). A folder with a year or provider ID contains one work. A folder that owns by title alone contains its own work and, beside it, the works of videos with longer titles. Its own work consists of the videos that carry its name followed by `-`, `_`, `.`, `[`, ` -` or ` [`, or that carry its title. That work is split by year when those videos state several years. Unrelated subfolders never disable ownership.
- **M2 Title source.** If the folder is trusted (`Title (Year)`, `Title [Year]`, a provider tag, or a release name with a year), the folder name gives the movie's title. Otherwise the title is parsed from the file name. Both parses are returned as evidence. If a trusted folder and a trusted file contradict each other, the movie is ambiguous. Disc-rip track names (`title00`, `t01`, `VTS_01_1`) give no title.
- **M3 Year.** A bracketed `(YYYY)` / `[YYYY]` before any release word is the year. Otherwise the year is the last bare year before any release word that is followed by release words or by nothing. A year after release words is never the year, with or without brackets. A leading number is part of the title (`1917.2019.1080p` → `1917`, 2019). Date shapes are not years. In `Title 2019 (2019)` the bare number stays in the title, unless the owning folder confirms both title and year. The interpreter makes that decision.
- **M4 Release words.** Release words form two tiers, both data. Technical words (resolution, codec, source, audio, HDR formats, container names such as `MP4`) end the title wherever they occur. Words that can be ordinary title words (`German`, `Limited`, `UHD`, `4K`, `Opus`, `Web`, `Multi`, edition words, …) end the title only after a year or a technical word, or, in a release name, when only release material follows them. A name is a release name if it has no spaces, joins words with dots or underscores (`Super movie.3d`, not `Mr. Robot`), or contains a technical word, a year or a release bracket. So `Crouching.Tiger.Hidden.Dragon.UHD` → `Crouching Tiger Hidden Dragon` and `Movie 2019 Multi` → `Movie`. Clean titles keep their words: `Mr Holland's Opus`, `The Web`, `Super movie Multi`, `The 4K Project` (owner decision). If a name contains only release words, the whole name is the title. The title ends at a dash that is followed by a short number and then by release material or by nothing (`Title - 13 [720p]`).
- **M5 Brackets.** The parser drops metadata brackets (CRC32 checksums, multi/dual audio or subtitle markers, unfilled templates), provider and edition tags, and bracket groups after the title that contain only release words or a number. A leading bracket is a release group, and is dropped, when its text ends like a group name (`…Subs`, `…Raws`) or when release words follow it in the name (`[Grp] Title [1080p]`). Otherwise it is part of the title (`[REC] 2`, `[Grp] Movie Title`).
- **M6 Separators.** Dots and underscores become spaces when the name has no spaces. Dotted acronyms are kept and written with their final dot (`A.I.Artificial.Intelligence` → `A.I. Artificial Intelligence`, `S.W.A.T.S01E02` → `S.W.A.T.`). `Mr. Robot` keeps its dot. An extra's name counts as having spaces when any extra in its folder has spaces, so sibling extras are cleaned the same way (`Behind the visor_new` beside `Splashdown_new` keeps both underscores). Letter case is never changed.
- **M7 Provider tags.** A provider tag is `key-value` or `key=value` inside `[]`, `{}` or `()`. The keys are `tmdb`, `imdb`, `tvdb`, `tvmaze`, `anidb`, `anilist` and `anisearch`, each optionally followed by `id`, as data (X29). Values are validated (positive integers; IMDb `tt` + 7-10 digits). A bare ID of a prefixed shape, such as `tt…`, counts only inside brackets or as the last token of the folder name. It then only fills a missing ID of that provider. Unsubstituted template tokens (`{TvdbId}`) are ignored. An unknown key gives no provider ID; in curly braces it is reported in `tags` (X29). The full path is never scanned.
- **M8 Provider precedence.** For each provider, the owning folder's ID takes precedence, and the file's ID only fills a missing one. If two sources give different values for the same provider, the ID is ambiguous and both claims are kept. Names at or above the library root give no provider IDs.
- **M9 Editions.** The parser reads `{edition-X}` or `[edition-X]` as `edition`. The parser reads edition words after the title and year (`Extended`, `Director's Cut`, `Unrated`, …, as data) as an `edition_hint`, never as an edition. Editions of one film are one work. Each parse reports only the raw tag and hint of the name that it receives. A parse has no composed edition key or source, because only the interpreter knows which name (file or folder) carried them. Edition words before the year are part of the title (`Urban Legends Final Cut (2000)`).
- **M10 Versions.** Videos with the same owner and the same identity (title and year, or provider ID) are versions of one work. This also applies to videos loose at the root. A version's label is the text after the owner's title and year (`- 1080p` → `1080p`). If there is no such text, the label is the release words. The label excludes provider-ID and edition tags, because those are separate facts. So `{tmdb-1} {edition-Cut} - 2160p` is labelled `2160p`, and a version that adds only tags has no label. Each version carries its own `edition`, `edition_hint` and 3D layout. These come from the version's name, else from its folder's name (M9). A movie with one version has no label. The video named exactly as its folder comes first. The other versions follow, ordered by the resolution at the start of their label (highest first), then by label, then by path. Videos in different folders are never merged, even when they have the same provider ID. The caller's catalog merges works across locations.
- **M11 Parts.** A part marker is `cd`, `dvd`, `disc`, `disk`, `part` or `pt` followed by a number or a letter `a`-`d` at the end of the stem, or a folder such as `CD1/` or `Disc 2/`. A stack needs at least two parts, contiguous from 1 or `a`. Gaps or duplicates make the parts ambiguous. `scene` and `vol` never mark parts. Entries in one folder form a stack when their names before the marker match, ignoring case, and their markers are the same kind (numbers or letters). The stack's name is that shared text. A part word glued to the title (`300a`) or followed by more text is not a marker.
- **M12 3D.** `3d` together with `sbs`, `hsbs`, `fsbs`, `tab`, `htab`, `ftab` or `mvc` sets `format_3d` to that layout. A bare `3d` sets `format_3d` to `unspecified`. A layout word alone (`Movie.hsbs`, `sbs3d`) also sets its layout. `sbs` and `tab` mean `side_by_side` and `top_and_bottom`. They are never read as the half variants. Only words after the title count. Two different layouts make the 3D format ambiguous.
- **M13 Disc structures.** `VIDEO_TS/`, `BDMV/` and `.iso` / `.img` are reported as disc structures. The caller decides whether they can be played. In an interpreted tree, the folder that contains `VIDEO_TS/` or `BDMV/` is one version, and the version's path is that folder. Disc folders with part markers are ordered parts (M11).
- **M14 Stub files.** Stub files are not supported. A `.disc` name is parsed like any other name (container `disc`). No stub fields are reported.
- **M15 Episode names in a Movies library.** A video with an episode name in a Movies library is still a movie. It is ambiguous with reason `episode_token_in_movie_library`, unless a provider ID on its owning folder fixes its identity (M1). If the file is under a season folder, it is reported as misplaced series content. The title is the text before the episode token. Only an explicit token (`S01E02`, `E02`) counts. A bare number (`02.mkv`) or a dash number (`Show - 12`, M4) does not make an episode name, so the movie stays resolved.
- **M16 Alternate titles.** A movie name that states several titles gives the first one as the title and the others as `alternate_titles`, in name order: the text after `AKA` (any case, between separators), the text after ` / `, and a trailing parenthesised group of words after the title (`Battle Royale (Batoru Rowaiaru)`, `Stalker (Zona)`). Square brackets stay part of the title (`[REC]`), and `aka` inside a word is no separator. A movie states the alternate titles of the name that gives its title (M2). A folder title agrees with a file title (M1) if any title of the one agrees with any title of the other, so `The Prestige (2006)` owns `Le.Prestige.(The.Prestige).2006.mkv`. Rendering writes the title only.

## TV

- **T1 Series folder.** The series folder is the parent of the nearest season folder. If there are no season folders, it is the folder that contains the episode files. Category folders between the root and a show are allowed (`TV/Kids/Show/Season 01/`). A same-named wrapper (`Show/Show/Season 01/`) collapses into one folder. A folder that contains differently named shows (`Doctor Who/Doctor Who (1963)/`, `Doctor Who/Doctor Who (2005)/`) is a category, never one series. A season folder may contain one more season folder (`Season 01/Specials/`). The series folder is then the parent of the outer one. A season word alone (`Season/`, `Staffel/`) below a series folder is season structure without a number. A season folder at the library root is its own series folder, because no folder above it can be a series folder. If a folder that looks like a season folder has the file's series title as its name or title, it is the series folder instead (`Drama/24/Extras/24 S00E02`, `Genres/Season/Season.S01E01`). The series folder is the series' path also when the series title comes from a file (T2). If two shows in one folder take their titles from repeated file texts, the folder contains two series. A series loose at the root has no path.
- **T2 Series name source.** A trusted series folder always gives the title of its series, whatever text its files repeat. The series folder gives the series title when the folder is trusted (it contains the season folder, or carries a year, a provider tag or a season such as `Show.S01.1080p`), when the file's series title agrees with it, or when the file has no series title. Otherwise, in an interpreted tree, the text before the episode code is the episode's title, and the folder still gives the series title (`The X-Files/Pilot - S01E01` → `The X-Files`, S01E01, `episode_title` `Pilot`). The exception is when files of several episodes in that folder repeat the same text. That text is then the title of a separate series in the folder, and the folder is a category (`Cartoons/Peppa S01E01`, `Cartoons/Peppa S01E02` → `Peppa`, path `Cartoons`). Several versions of one episode that repeat a text count as one episode. The same applies in a season folder of a trusted series folder. If a file's text before the code differs from the series folder's title (compared in the folded form of P4, so `Harbor Lights` agrees with `The Harbor Lights`), that text is the episode title, unless a title follows the code (`Show (2019)/Season 01/Low Tide - S01E01` → `Show`, `episode_title` `Low Tide`; `parse_episode_name` reports the same). If files of several episodes in that season folder repeat the same text, the trusted folder still gives the series title, and that text is offered as the series' `alternate_identity` (`Show (2019)/Season 01/Peppa S01E01`, `Peppa S01E02` → `Show`, path `Show (2019)`, alternate `Peppa` with no year). If the repeated texts differ between a series' seasons, no alternate is offered. Repeated text gives the title of a separate series only inside an untrusted category folder, as above. A folder whose name is only a season marker (`Season/` at the root) never gives a series title this way. The file's text gives the title instead. This decision needs the folder's other files. `parse_episode_name` reads one name, so it reports the text before the code as `series_name`, with the file's own path as `series_path`, and the interpreter makes the decision. A file that repeats the whole folder name keeps a season word in the title (`La Série 2/La Série 2 S01E03`). Titles follow M3-M6, except that a bare year at the end of a series name stays in the name (`Space 1999`). If the series title comes from the file and a token that states a season follows the year, the title without the year is also offered as `alternate_identity`, with that year (`Show.2020.S01E01` → `Show`, 2020). If the series title comes from the folder, a file's year counts only when the file's title agrees with the folder's title (`Show/Show.2009.S01E01` → 2009). If a series folder contains a season folder whose name is only a season marker (`Season 01/Specials/` at the root), the series title is the whole name of the series folder.
- **T3 Episodes loose at the root.** The series name is the text before an explicit episode token. If the file has no such token, it is unresolved. In an interpreted tree, a video that has neither a series nor a reference is not an item and stays unclaimed.
- **T6 Bare numbers.** These bare numbers are read as episodes: a leading number, ` - NN`, `[NN]`, and a trailing number after the series name. A compact `NNN` means season and episode only when a season folder's number matches its leading digit(s). Otherwise it is an absolute number. A number that is part of the series title (`The 100`) is not an episode. A number inside the series folder's title at the start of the name is not an episode either (`24/Season 1/24 - Title`). A compact number has three or four digits and no leading zero (`003` is episode 3). A leading `N-NN` outside a season folder is season and episode (`1-05` → S01E05). Inside a season folder it is a range. The order of precedence is: explicit tokens; then ` - NN` followed by the end, a dash, a bracket or release words; `[NN]`; a leading number; ` - NN` before title words; a number after the title; last a bracketed `NxNN` (`- 03 - Title (2x14)` is episode 3). A number directly followed by another number (`12 00 AM`) is a time, not an episode.
- **T7 No season evidence.** If a name has no season evidence, the season is unknown. The season never defaults to 1.
- **T9 Season folders.** Season folders are recognized by localized season words (data), ordinals, `S01`, release-pack folders (`Show.S01.1080p`), `Season 4 (2011)` and year-numbered seasons. A bare number is a season only directly under a series folder. `Series N` is a season only directly under a series folder. A folder's arbitrary trailing number is not a season. Text before the season marker must be the parent series folder's title (`Fargo - Season 2` under `Fargo`). If the text is not that title, or if the folder has no parent, the folder is not a season (`Disc 1 Season 2`, `Seinfeld Season 2` under `Drive`). `Serie`, `Série`, `Seria`, `Séria` follow the `Series N` rule. The caller supplies whether the parent is a series folder (`parent_is_series_folder`). The episode parser assumes it for any folder with a parent. A top-level release folder (`The.Show.S01/`) is the series folder and gives its season to files that have none.
- **T11 `Extras/` in a show.** `Extras/` in a show is an extras folder, never season 0. Inside it, only a token that states season and episode (`S01E01 - Behind The Scenes`) is read, as the owner's coordinates. `E02` or a bare number is not an episode.
- **T12 `SPnn`.** `SPnn` is season 0, episode `nn`.
- **T13 Dates.** A year-first date (`YYYY-MM-DD`, `-._ ` separators, also in parentheses or before a time) is read as a date reference. No season is invented. A day-first or month-first date is a date only when it is unambiguous (a part above 12). Otherwise it is ambiguous. An episode token directly next to the date also counts (`2024-10-01 - 2024x246`). In other positions such text is part of the title (`2x4 Vandalism`). Bare numbers never count beside a date.
- **T14 Absolute numbering.** Absolute numbers are reported as `absolute`, with the release group, checksum, `vN` and `END` removed. Mapping them to seasons needs metadata that the caller supplies. Absolute numbers are never reported as `episodes`. A season folder's season is still reported (`Season 21/301` → season 21, absolute 301).
- **T15 Multi-episode.** A multi-episode name gives the explicit list of episodes. A dash or tilde pair is an inclusive range (`E01-E03`, `E01~E03`, compact `301-305` within one hundred). Non-contiguous lists stay as listed. Gaps are never filled. A chain of three or more is a list (`E07-E08-E10` → 7, 8, 10). A pair of compact or absolute numbers is a range only within one hundred (`301-405` → 301). A continuation must keep the token's style and season. So ` - E2` after `S03E21` and `-S02E01` after `S01E10` end the list.
- **T16 Number guards.** Resolutions, aspect ratios, codecs and audio layouts (`1920x1080`, `16x9`, `5.1`, `x264`) are never seasons or episodes. Seasons are 0-99 or a year. Episodes have at most 5 digits. A token with an invalid season (`S999E01`, `Season 345 Episode 8`) gives no season and no episode. It is not read as an episode alone.
- **T17 Episode versions and parts.** Videos of one series with the same season and coverage (episode list, absolute numbers or date) are versions of one episode item, also when their titles differ. Part markers stack them into ordered parts (M11). A version's label is the release text that remains after the episode reference and the episode title (T19). The label is never the title itself (`Show - S01E01 - Pilot - 1080p` → `1080p`). A version whose title takes all its text (`Pilot (MP4)`) has no label. The version with no text after the episode reference and title comes first. The other versions follow, ordered by the resolution at the start of their label (highest first), then by label, then by path. A multi-episode file is one episode item that lists every episode it covers. Coverages that overlap without being equal (`S01E01-E02` beside `S01E02`) stay separate items, each with its full coverage. No file's coverage is trimmed or duplicated. Each season that an episode states is a season item. The season item's path is the one season folder that contains that season's episodes. A season in a release pack or in several folders has no path.
- **T18 Nested episode folders.** Episode videos may be one extra level below a season folder (`Season 01/Disc 1/`, a folder per episode). The episode token comes from the file, else from that folder. A folder per episode directly in the series folder also counts (`Dexter/Dexter - S01E01/`) when its series title is the series folder's title. A release folder with another title is a series folder of its own.
- **T19 Episode titles.** The cleaned text after the episode token or air date is returned as `episode_title`. If release words follow the token directly, there is no episode title. An interpreted episode carries its primary version's title, or the text before the code when T2 makes that text the title. In a TV library, a title after a spaced dash that follows an explicit episode token is the episode title, even when it is an extras word (`Show - S01E02 - Other`, `Show S01E01 - Behind The Scenes` are episodes). Only a glued suffix makes an extra (E5). A title keeps its own punctuation and numbering: a leading ellipsis (`...And Found`), an acronym's final dot (`S.O.S.`, M6) and a bracketed part number (`Live Together, Die Alone (1)`). Only release-word brackets after the title are dropped (M5).
- **T21 Recording channel tags.** When a run of underscore-joined words is directly followed by a date, the series title ends at the first underscore after the last space-separated word: `Last Man Standing_KTLADT_2018_05_25_01_28_00.wtv` → `Last Man Standing`, 2018-05-25. A space before the date keeps the underscore (`Mr_Robot 2015-06-24` → `Mr_Robot`). A name without spaces follows M6.
- **T20 Hints (owner decision).** No hints file is read. The caller supplies hints per root-relative path of a file or a folder (`inputs.hints`). A movie hint (on its folder or on a video) sets `title`, `year` and `provider_ids`. In TV, those fields set a series' facts when the hint is on its series folder. On a video without a series folder, `title` and `year` set the series name and year of its episode, because no series folder can carry them; `provider_ids` there is not applicable, because R2 writes the ID on the series folder only. `series_folder` marks one of a video's folders as its series folder. `season` sets the season of the videos at or below the path. On a folder whose own name states no season, `season` also makes that folder a season folder. `episodes` sets the episodes that a video covers. If the names leave out a fact, the hint fills it (`filled`). If the names state the same value, the hint agrees (`agreed`; titles compare in comparison form, P4). If a hint contradicts a name, the name's value is kept and the item is ambiguous (`hint_contradicts_name`; a provider ID becomes ambiguous between both values). If the hint is `authoritative`, it replaces the name's value instead (`overrode`). Every hinted fact is recorded on its item with its outcome and the names' value. Hints settle facts, not structure. Hints never merge or split items; overrides do that. These cases are input diagnostics: a hint for a path outside the listing (`unknown_path`), a hinted fact that no item at the path takes (`not_applicable`), and a path that several hints target (`duplicate`; none of these hints applies).

## Extras

- **E1 Folder vocabulary.** The extras folder vocabulary is `Trailers`, `Teasers`, `Backdrops`, `Theme Music`, `Behind The Scenes`, `Deleted Scenes`, `Interviews`, `Scenes`, `Samples`, `Shorts`, `Featurettes`, `Clips`, `Bloopers`, `Other`, `Extras`, `Extra`, as data, matched ignoring case and spacing. Each word maps to its own kind: `Extras` and `Extra` map to `extra`, `Other` maps to `other`, `Teasers` maps to `trailer`, `Backdrops` maps to `theme_video`, `Theme Music` maps to `theme_song` (audio only). Inside an owned extras folder, the nearest vocabulary folder determines the kind (`Extras/Behind The Scenes/clip.mkv` is behind the scenes).
- **E2 Ownership.** A vocabulary folder is an extras folder only when its parent owns feature media (a movie, series or season). Otherwise it is an ordinary folder, so `Movies/Shorts/Film (2020)/` stays a movie. Ownership is judged only from the supplied entries. The parent owns feature media when it contains a video that is not itself an extra, directly, in a season folder, or one level below a season folder. A folder at the library root has no owner. A vocabulary folder that contains season folders of episode-coded videos is a series of its own (T1), not an extras folder.
- **E3 Suffixes.** An extras suffix is `-`, `.`, `_` or ` - ` followed by the extra word and an optional index (`-trailer2`), with a title before it. Each suffix word maps to its own kind, as in E1 (`-interview` is an interview). The extra's title is the text before the suffix. In an interpreted tree, that title is read like a movie name (`Trailer 1 (2013)` → `Trailer 1`, 2013; release tags dropped). An extra's title never comes from its type, and extras are never numbered by count. `classify_extra` returns extra roles. `parse_movie_name` reports none. In a TV library, a suffix with a space beside its separator after an explicit episode token (`S01E01`, `E02`, `1x02`, `SP02`) is the episode title, not an extra (T19).
- **E4 Exact names.** `trailer.<video>`, `sample.<video>`, and `theme.<audio>` (theme song) are extras. `trailer.mp3` and `theme.mkv` are not.
- **E5 Episode suffix extras.** `Show S01E05-deleted.mkv` is an extra owned by S01E05. The suffix must be glued to the name (`-`, `.` or `_` without a space beside it). `Show S01E05 - Deleted` is an episode titled `Deleted` (T19).
- **E6 Samples.** A sample is an extra of kind `sample`, recognized by exact name, by suffix, or by a `Samples/` folder. A sample is never excluded because of a substring or because of its size.
- **E10 Opening/ending videos.** Openings and endings are the extra kinds `opening` and `ending` (X31), read from the folders `Openings` and `Endings`. No suffix or exact name states them, because `The.Ending.mkv` is a title.
- **E11 Attachment.** An extra is attached to the item in its folder that its name refers to (a video stem, a stack name, or the same title with no differing year). For the contents of an extras folder, the search uses the folder that owns the extras folder. If no item matches and the folder is outside the library root, the extra is attached to the folder's only item, or to the one item that is the folder's own work (M1). Any other extra is an orphan item of kind `extra`. The orphan is ambiguous when several items tie. Extras classification judges ownership only from entries that the ignore rules keep. In a TV library, an extra is first attached to the one episode, among the episodes in or above its folder, whose season and episode its title states (E5, T11). The episode code is then only the owner reference, and the extra's title is the text after the code (`Deleted Scenes/S01E01 - Cut` is titled `Cut`; `Show S01E05-deleted` has no title). Otherwise this rule applies with the series and season folders as their items' folders. So an extra in a season folder or in its extras folder is attached to the season, and an extra in the series folder is attached to the series.

## Sidecars and assets

- **S1 Subtitle formats.** The subtitle formats are `srt`, `ass`, `ssa`, `vtt`, `sub`+`idx` (one pair), `sup`, `smi`, `sami` and `mks`, as data. Recognizing a format does not mean that the subtitle can be played.
- **S2 Locations.** Subtitles are found beside the video, in `Subs/` or `Subtitles/`, and in `Subs/<video stem>/`.
- **S3 Matching.** A subtitle matches a video when its name starts with the full video stem followed by a delimiter. The longest matching stem takes precedence. Among equal stems, the stem that matches letter case exactly takes precedence (`movie.en.srt` beside `Movie.mkv` and `movie.mkv`). Other equal matches are ambiguous and stay unattached. In a folder with a single feature, descriptor-only names in `Subs/` (`English.srt`) are attached to that feature.
- **S4 Language and flags.** Languages are returned as BCP 47 tags (`en`, `pt-BR`, `zh-Hant`), with the raw token kept. The flags are `default`, `forced` (also `foreign`) and `hearing_impaired` (`sdh`, `cc`; `hi` only when another language is present, otherwise `hi` is Hindi). The `.`-separated words after the video stem are read in any order. ISO 639-1 and 639-2 codes and English names map to their tag through a language table (data). Codes that are common words (`cat`, `may`) are left out of the table. Two different languages in one name make the language ambiguous. Neither the first nor the last language takes precedence. Words that are neither language nor flag form the `title`, joined by `.`.
- **S5 Other sidecars.** External audio tracks are matched with the subtitle matcher. Lyrics are out of scope.
- **S6 Video stills.** An image named exactly like a video, or like the video plus `-thumb`, is that video's still (artwork role `thumb` of its movie). Any image extension counts. Other suffixes (`-poster`) are artwork roles (S7), not stills. An episode's still has the role `episode_still`.
- **S7 Artwork.** The artwork role vocabulary is the widest established one, as data. The roles include `clear_art` (written `clearart`) and `disc_art` (written `discart`, also read from `disc`) (X31).
- **S8 Generic names.** Generic artwork and NFO names (`poster.jpg`, `movie.nfo`) belong to a folder only when the folder contains a single title.
- **S9 NFO names.** An NFO's role is determined by its name. Its contents are never read. `<video stem>.nfo` belongs to that video's item (a movie or an episode). An NFO with the shared name of stacked parts (`Movie-cd1.mkv` → `Movie.nfo`) belongs to their movie. `movie.nfo` belongs to its folder's movie, `tvshow.nfo` to a series folder and `season.nfo` to a season folder. Names are matched ignoring case. A video's own name takes precedence over a generic name (`movie.mkv` beside `movie.nfo`). Generic names apply only in single-title folders (S8), and the interpreter decides which folders those are: `movie.nfo` in a folder that contains one movie, `tvshow.nfo` in the folder of exactly one series, `season.nfo` in the folder of exactly one season, never at the library root. An NFO with any other name is not attached to an item. Each version takes the NFO named after its video, or after its parts' shared name, as its `nfo` (`Movie - 1080p.nfo` beside `Movie - 1080p.mkv`). An NFO named after the version's own video takes precedence over one named after its stack. An item's `nfo` is its primary version's `nfo`, else the generic NFO of its folder. A generic NFO beside a primary version's own NFO stays unclaimed. Every NFO attached to a version or an item is claimed, so no NFO named after a claimed video is reported unclaimed. The planner moves each version's NFO with that version. An NFO named after a video is renamed to that video's new stem. An NFO named after a stack is renamed to the version's new name without a part. An item's generic NFO stays in place in the renamed folder.

## Ignore

- **I1 Rule sources.** Rules come from `.ignore` files and the `.nomedia` marker. The marker excludes its folder, whatever the folder contains. Callers may supply further rule sets per directory in the same syntax. Every supplied file other than `.nomedia` is read as rules for its folder.
- **I2 Syntax.** Rule files use gitignore syntax (comments, `!`, `**`, trailing `/`, escapes; a backslash makes any character literal). Surrounding whitespace is trimmed from each line. A backslash keeps a trailing space. An invalid line (unclosed `[`, unknown `[:class:]`, trailing `\`, a lone `!` or `/`) produces a diagnostic with its line and matches nothing. The other lines still apply. A UTF-8 byte order mark at the start of a rule file is not part of its first line.
- **I3 Anchoring.** Patterns are relative to the directory of the file that contains them.
- **I4 Nesting.** Rule files stack from the library root down. The last matching pattern takes precedence. Files in one folder are applied in path order.
- **I5 Empty file.** A rule file without pattern lines (empty, blank or comments only) excludes its folder and everything below it. A file whose lines are all invalid is not empty. It produces diagnostics and excludes nothing.
- **I6 Hidden entries.** A name that starts with a dot is excluded, with everything below it.
- **I7 NAS and OS junk.** The built-in junk names, such as `@eaDir`, `#recycle`, `$RECYCLE.BIN`, `lost+found`, `.zfs`, `thumbs.db` and sync-tool temporaries (`.sync`, `.bts`), are data. They are matched as whole names, ignoring case.
- **I8 Built-ins first.** Built-ins are checked before rules, and no rule can re-include an entry that a built-in excludes. As in git, no entry below an excluded folder can be re-included.
- **I9 Content-like folders.** `Subs/`, `extrafanart/`, samples, extras folders, theme files, artwork names (`small.jpg`, `albumart.jpg`) and disc folders are classified, not ignored. These are ignored by default, as data: `metadata/`, `.trickplay` folders, `.actors/` and partial-download suffixes (`.part`, `.!qB`, `.crdownload`).
- **I10 Unreadable rules.** An unreadable rule file makes its scope incomplete. It never means "include all" or "exclude all". Its folder and everything below it are undecided, with the file's path reported, unless a built-in or an excluded folder above already decides the outcome.
- **I11 Case.** Patterns are matched ignoring case (X2). POSIX classes such as `[:upper:]` are tested against the character as written.

## Cross-cutting

- **X1 Library root.** Inputs are root-relative. No entry at or above the root supplies a title, year, provider ID or rule. A rule file whose path is outside the root produces a diagnostic and is not applied.
- **X2 Case folding.** Case folding is locale-independent Unicode case folding.
- **X3 Unicode.** Comparisons use NFC. Output keeps the raw text.
- **X4 Non-UTF-8 names.** Non-UTF-8 names are reported per entry as `unsupported_encoding`. They are never decoded lossily.
- **X5 Years.** Valid years are 1900-2099. The clock is never read.
- **X6 Ambiguity.** Ambiguity is per fact, with a reason. The other facts of the same entry stay usable.
- **X7 File types.** Extension lists are data. `.strm` is not a video.
- **X8 Parser context.** Parsers take only explicit context about the caller's tree: `parent_name` and `parent_is_series_folder` for season folders, `season_folder_number` for episodes. Parser switches from other servers (`allow_bare_number`, `top_level`, `support_special_aliases`, `supports_absolute_numbers`, `is_named`, `is_optimistic`, `library_folder_name`) are not inputs. The behaviour that those switches controlled is either always on, decided by the rules above, or never read (X1).
- **X9 Rules.** Every input vocabulary (what an existing name means: release, edition, extras, season, specials, language and flag words, provider keys, extensions, artwork and NFO names, built-in exclusions, comparison folds) is stored in one rules value. Every operation runs under one rules value, by default the built-in rules. The output profile, never the rules, defines how names are written (extras output folders, flag spellings, reserved device names). Interpretations, plans, validations, rankings and every wire response carry the identity of the rules that produced them. Per-name parser results do not carry it, because the caller already has the rules that it passed. Plan and validate an interpretation under the rules that produced it. Word alternations are matched longest first, so a vocabulary's order never changes a result.
- **X10 Overlays.** Callers change vocabularies through overlays, never through code. Each overlay is one YAML or JSON document with a unique `name`, an optional `version`, and `add` and `remove` per vocabulary (word lists; maps from word to extra kind, artwork role or NFO role; language tags to spellings). Entries are normalized the same way that their vocabulary compares names (case, NFC, extras words without separators, extensions without their dot). All overlays are applied together onto the built-in rules. If two overlays change one entry differently (one adds what another removes, or they give it different kinds), or if two overlays share a name, the conflict is reported and no rules are built. The declared order is used only for the order in the identity. Each overlay's identity carries a digest of its changes, so an edited overlay never has the same identity as the old one. Edition phrases are matched longest first, so the effect of an added phrase never depends on its position. An overlay is rejected, with the line of the faulty entry, when it lists an entry twice in one vocabulary (however written, or added and removed), when it adds a word that the grammar already reads to a vocabulary of name words (a year, an episode code, a resolution or codec, a release version, a bare number: `reserved_token`), or when it adds a word that a rival class still contains (`colliding_entry`: technical, title-like and edition words; default, forced and hearing-impaired flags; season and series-season words). To move a word between rival classes, one overlay adds the word to one class and removes it from the other. Language packs and user overlays are two layers (X32): only overlays of one layer can conflict.
- **X11 Languages (owner decision).** The built-in rules are the shared base (`crates/nomenclator/data/builtin.yaml`) with every language pack applied, so if no languages are declared, the rules contain the words of every language. A caller may declare a library's languages (BCP 47 tags with a language pack). The rules then contain the shared base and exactly those languages' packs. The base holds no word of a pack (tested). A pack is an overlay shipped as data (`crates/nomenclator/data/languages/<tag>.yaml`). A pack contains season, series-season and episode words, leading articles, spelled numbers, ordinal suffixes (`2nd`, `3.`, `2ème`) and the language's own names (`deutsch`). The shared base keeps the words that the output profile writes and the release conventions that all libraries use: `Season`, `Specials`, extras, edition and release words. So in an English-only library, `Die Hard` does not match `Hard`, and `Staffel 2` is no longer read. A German library reads `Movie.deutsch.srt` and reads `Teil Zwei` as `Teil 2`. A declared language without a pack is a diagnostic (`unknown_language`). Packs never conflict with each other (tested). Leading articles, number words and ordinal suffixes are overlay vocabularies too. A pack also adds the language's artwork role words (`locandina` is a poster in `it`, `hintergrund` a backdrop in `de`, 4.6); the English artwork words (S7) belong to the shared base.
- **X12 Presets (owner decision).** Caller data may choose another alternative for a contested decision, but only an alternative that the decision catalogue records. The defaults are the decisions. Presets are set in an overlay's `presets` section (a mapping from preset to value). So overlays that set one preset differently conflict, and the identity digest covers the presets. `latest_plausible_year` (X5): a year from 1900 to 2099, the latest year that a name's number or date can state. `earliest_plausible_year` (X5): a year from 1800 to 2099, 1900 by default, the first year that a name's number can state. `date_order` (T13): `ambiguous` (default), `day_first` or `month_first`, which settles only dates for which both readings are valid. `bare_numbers` (T6): `anywhere` (default) or `season_folders_only`, where a bare episode number needs a season folder. `ignore_nesting` (I4): `stack` (default) or `nearest`, where the patterns of the nearest folder that has patterns replace its ancestors' patterns (markers and built-ins still apply). `samples` (E6): `extras` (default) or `excluded`, where an interpreted sample is an excluded entry (`sample`). Samples are still recognized as E6 states, never by a substring or size. An unknown preset or a value outside these is a diagnostic on its line (`unknown_preset`, `invalid_preset_value`).
- **X13 Built-in ignore groups.** The built-in exclusions are four groups, all on by default: `hidden_entries` (I6), `system_junk` (I7), `partial_downloads` and `generated_metadata` (I9). An overlay turns one group off with `built_in_ignore_groups: { remove: [...] }`. The group's entries are then handled by the rule files like any other name. This is an opt-out that the caller requests, not a preset (X12). I6-I9 are agreed decisions, and no preset chooses another reading for them. Their word lists are also overlay vocabularies. A group name outside the four is a diagnostic (`unknown_entry`).
- **X14 Ignore dialects.** Each supplied rule file states its dialect. `gitignore` (the default, I1-I11) keeps negation, escapes and folder-only patterns. `glob` is one glob per line. In `glob`, a pattern without `/` matches a name at any depth, a pattern with `/` is relative to the rule file's folder, `#` starts a comment, and `!` and `\` are part of the name. Matching ignores case as in I11. The caller chooses which file names are rule files, because the caller supplies them. The no-media marker names are an overlay vocabulary, `no_media_markers` (default `.nomedia`, compared ignoring case).
- **X15 Rules diff.** `diff_rules` interprets one listing under two rule sets and reports, per path, only the facts that differ. Each fact has its value under each set (absent where a set states no value). A path's facts are its outcome (`item`, `excluded`, `undecided`, `invalid`, `unclaimed`) and reason. For an item's file, the facts also include its role and the facts of the item that it belongs to: movie or episode identity, version label and edition, extra kind, title and owner, sidecar language and flags, artwork role. Paths and facts are sorted, so a diff never depends on the order of the listing. The CLI's `nomenclator diff --rules A --rules B` exits with status 1 when any fact differs, like a file diff.
- **X16 Overrides.** The caller decides the structure that the names cannot settle. Overrides are supplied per call (`inputs.overrides`) and are never stored. `merge` lists groups of videos that are versions of one item. That item is the item of the first video listed, and it keeps its identity. In TV, the other videos take its series, season and coverage. `split` lists videos that become items of their own. A split movie takes its title from the video's own name and is owned by no folder. A split episode is separate from the videos with the same coverage. `extras` sets an extra's `kind` and its `owner`. On a feature video, `kind` makes the video an extra, titled by its name. `owner` is a folder, and that folder's own item takes the extra without title matching (E11). Hints (T20) settle facts. Overrides settle structure. A path outside the listing (`unknown_path`), or a path that is not a video or extra as the override requires (`not_applicable`), is an input diagnostic.
- **X17 Numbering and episode orders.** For each series (`inputs.series`, identified by its folder, or by title when it has no folder), the caller states the order in which its names number episodes: `aired` (the default), `dvd`, or `absolute`, where a number without a season is an absolute number (T14). The caller can also supply numbering maps into the aired order: `absolute` ranges per season (`first`-`last` are that season's episodes 1, 2, …) and `scene` pairs. A map applies only when it covers every number of a name in one season. If an absolute map's season differs from the season folder's season, the episode is ambiguous (`numbering_contradicts_season`). A mapped episode keeps its absolute numbers and states the numbers it replaced (`mapped_from`). A mapped episode is in the aired order, so it is a version of the episode at those coordinates. If series inputs or an `episode_order` hint are supplied, every episode states the order of its coordinates (`order`; `absolute` for absolute numbers only). One coordinate in two orders is two episodes. Without series inputs or that hint, no order is stated. Series inputs that no episode takes are input diagnostics. A rename plan writes an episode's coordinates in the order that its names use, so a library in one order stays in that order; one coordinate in two orders renders one name twice and is blocked as a collision (R6).
- **X18 Reference metadata.** Only validation reads the catalogue facts that the caller supplies (`reference`: movie years by path or provider ID, and series episode lists as aired `[season, episode]`). These facts never change an interpretation. A reference year never fills a missing year. If a movie year differs, validation reports `reference_year_mismatch` (warning, reason: the reference year). An episode that the list lacks is reported as `unexpected_episode` (warning). A listed episode that the library lacks is reported as `missing_episode` (info, on the series folder). Both diagnostics have reason `SxxEyy`. Episodes in an order other than aired (X17) are not compared. A series that contains any such episode is not checked for missing episodes, because its aired coverage is unknown. Reference entries that no item takes are input diagnostics of the validation.
- **X19 Release facts.** `parse_release` reads the release facts of a name: resolution, source (with `remux` and `screener` flags), video codec, bit depth, HDR formats, audio codecs and channels, audio and subtitle language markers, release group, checksum, revision, streaming service and container. Every fact is optional and carries its span; one fact stated with two different values is ambiguous. The vocabulary is data (`release_words` in `crates/nomenclator/data/builtin.yaml`): each value lists its spellings, and a space, `.`, `-` or `_` in a spelling matches any of them or none. Release words count only after the title. The title ends where the movie title parser cuts it, or earlier at the first strong signal after the first word: a resolution, a year, a technical word or a release word with a digit. A word that can also be a title word (`Cam`, `Real`, `DV`) counts only after that position. An explicit height takes precedence over `4K`; dimensions and a frame rate give the height (`1920x1080` and `1080p24` are `1080p`). A plain `HDR` is `hdr`, not HDR10. The release group is the part after the last `-` of the last token (a single-letter lead keeps its dash: `D-Z0N3`), without index-site tags and checksums after it, else a leading `[Group]`. Full language names after the title are audio language markers; short codes are not read, because they collide with groups and words. The comparison with public test sets is in `docs/release-facts.md`.
- **X20 Fansub grammar.** A leading `[Group]` is the release group (X19), and ` - NN` is an episode number (T6). A revision after the number (`12v2`) is `release_version`, and `END` after it sets `is_final`; neither is part of the episode title. `S2 - 03` gives season 2, episode 3. An `OVA`, `OAD` or `ONA` marker after the first word, with an optional number, and a decimal number after a dash (`- 12.5`) are specials: season 0, `special` `{ kind, number }` with the number as written, and no `episodes`, because the name does not state the special's number in the season 0 order. A hint or a numbering map supplies the episode. Until then, the special is not renamed (`missing_episode_reference`). An explicit episode token takes precedence over a special marker, and a marker inside a word (`Nova`) is not read. Specials group apart from numbered episodes. A batch folder (`[Group] Title (01-12) [1080p]`) is the series folder, and its title is the text without the group, the range and the release tags.
- **X21 Library type suggestion.** `suggest_library_type` counts the videos of a folder, extras left out, that have an episode signal: an explicit season and episode, an air date, a special (X20), or a season folder above them. A bare number is no signal, because a movie title can end in one. The suggestion is `tv` if at least 90% of the videos have a signal, `movies` if at most 10% do, ambiguous (`mixed_names`) between them, and unknown without videos. The videos of each side are the evidence. The library type remains an input: no other operation reads the suggestion.
- **X22 Release junk.** A file is release junk if its name is a tracker note (`RARBG.txt`), its stem starts with a release note prefix (`Torrent downloaded from ...`), its extension is a shortcut or an executable (`.url`, `.lnk`, `.exe`, `.bat`), or it is an image whose stem is a screenshot or bitrate word with an optional number (`screen1.jpg`, `bitrate.png`). Media files are never junk. The lists are data and overlay vocabularies (`release_junk_names`, `release_junk_prefixes`, `release_junk_extensions`, `release_junk_images`). Junk is classified, not excluded: it is never artwork or a sidecar, it stays in `unclaimed_files` and moves with its folder as any unclaimed file does (R6), it is listed in `release_junk`, and validation reports it as `release_junk` (info) instead of `unclaimed_file`. A banner image stays artwork (S7), because `banner` is an artwork role.
- **X23 Scopes.** A scope is a folder at the library root with every entry below it, or the files at the library root (`Rules::scope_of`). The names in one scope never change the interpretation of another scope: a property test interprets every corpus tree, and trees that join the paths of eight cases, by scopes and in full, and the merged result equals the full one. Only an override joins scopes, when a `merge` group or an extra's `owner` names another scope; `Rules::scope_groups` returns the scopes that the overrides join. `interpret_scopes` interprets one group with the ignore files at the library root and inside the group. Its result has no input diagnostics, because an input for another group is not unused. `merge_scopes` combines the groups' results in the order of the full interpretation and reports the input diagnostics for the whole listing. A caller re-interprets only the groups whose entries changed. Rename plans and validation read the whole library, because a destination in one scope can collide with a file of another scope; they take the merged interpretation. On the wire, a `scope_group` on an Interpret query selects one group.
- **X24 Streaming and scale.** `InterpretStream` takes one tree in batches: the first message carries the header (handle, library, ignore files, inputs, scope group, rules), and every message can carry paths. The server moves each batch's strings into one listing and drops the message, so a tree larger than one message is never held twice in transport form. A header in a later message, or a first message without one, fails as an invalid argument. The library itself takes the whole listing, because the interpreter's passes read the whole listing (X23 limits a call to a scope group instead). `just bench` measures movie and TV libraries of exactly 1k, 10k and 100k entries and the re-interpretation of one scope group, asserts bounds of 10 s for 100k entries, and writes `target/benchmarks.json`; CI runs it on every push and keeps the report as the `benchmarks` artifact.
- **X25 One schema, read broadly.** Each canonical name that the writer writes is defined once, in the canonical section of `data.rs`: the artwork names (`poster`, `fanart`, `banner`, `clearlogo`, `landscape`), the generic NFO names, the NFO extension, the still image suffix, the episode letter `e`, the space separator, the written bracket pairs, the theme stem, the season folder word, the part word, the edition tag key, the extras folders and the sidecar flag words. The rules add each canonical name to the input vocabulary that reads it, and the input tables hold only the other spellings. An overlay that removes or redefines a canonical name is refused with `canonical_entry`, and a language pack that is not declared cannot remove one. The writer takes the rules, and it writes a provider ID only if the rules read it back: a known provider with a valid ID. A profile's own folder names are registered for reading in the form that the writer writes them. A property test renders every kind of name of a movie and a series under every profile layout, and interprets them back under the built-in rules and under each language pack alone; nothing is left unclaimed and every role, kind, flag and version comes back. The front ends call the core for every rule: the rules of a selection are built by `Rules::from_documents` or `Rules::for_languages`, where an empty language list selects every language; a conversion is `Rules::plan_conversion`; the CLI takes the core enums through the `clap` feature; and the corpus runners share one case loader. Every vocabulary is one row of the registry in `rules/vocabulary.rs`, which states the form that its entries are stored and looked up in (based on `lexical::vocabulary_form`: NFC, then a locale-independent case fold). The built-in vocabularies are one overlay document, `crates/nomenclator/data/builtin.yaml`, so built-in entries and overlay entries go through the same normalizer.
- **X26 Release vocabularies (owner decision).** The release facts read three overlay vocabularies (X10). `release_words` adds a map from release fact (`source`, `remux`, `video_codec`, `bit_depth`, `hdr`, `audio_codec`, `audio_language`, `subtitle_language`, `revision`, `streaming_service`) to normalized value to spellings, and removes spellings. A spelling is stored with its words separated by single spaces, so `WEB-DL`, `web.dl` and `web dl` are one entry (X19). A `bit_depth` value is a number. `audio_channel_words` adds a map from word to channel layout (`quad: '4.0'`); a layout is a digit from 1 to 9, a dot and a digit from 0 to 2. `release_site_tags` adds and removes the bracketed tags that name an index site, not a release group. The resolution words (`4k`, `8k`, `uhd`) stay fixed data, because the reader of version labels and the release parser share them.
- **X27 Document dialect.** Every YAML or JSON document is read with one dialect (`parse_document`): overlays, language packs, message catalogues, caller inputs, output profiles and corpus cases. Booleans are only `true` and `false`, as in YAML 1.2, so `no`, `off` and `y` stay strings (`no` is the Norwegian language tag). A mapping that repeats a key is a syntax error on the line of the repeated key.
- **X28 Reachable vocabularies.** Every table that the reader compares a name against is in the rules value and is an overlay vocabulary, and logic code contains none of its words. Besides the vocabularies of X10, X22 and X26, an overlay changes `part_words` (M11), `disc_folder_words` (T18), `subtitle_folders` (S2), `format_3d_words` (a map from word to 3D layout, M12), `release_group_endings` (M5), `video_heights` and `aspect_ratios` and `audio_codec_words` (T16), `letter_folds` (a map from one letter to its spelling, P4), `disc_image_extensions` and `disc_structure_folders` (M13), `unsupported_video_extensions`, `nfo_extensions`, `still_image_suffixes` (S6), `hearing_impaired_or_language_words` (a map from word to the BCP 47 tag that the word means alone, S4), `final_episode_words` (X20), `alternate_title_words` (M16), and `remux_markers` and `screener_markers` (text inside a release word spelling, X19). A video height is three or four digits, and a letter fold's key is one letter. A word only names a typed fact: an overlay maps it to an existing kind, role, flag or layout and cannot declare a new one. The codec words that the technical pattern read (`x264`, `h265`, `mpeg2`, `hdr10`) are technical words, so an overlay can remove them. The pattern keeps only shapes: resolutions, dimensions, bit depths and a codec joined to its channel count. An overlay that removes an entry that the built-in rules do not contain, and that no other overlay adds, is rejected with `ineffective_removal` on the entry's line, so a misspelled removal is never accepted without effect. The check reads the built-in rules and not the rules of the declared languages, so an overlay is valid under every language selection.
- **X29 Bracket tags.** The `tags` vocabulary maps a tag key to a typed fact: `edition`, or `provider_id` with an ID shape (`integer`, `slug`, or `prefixed` with a prefix and a digit range). A provider key may be followed by `id`. An ID that does not have its shape gives no ID. An overlay adds a key to name a typed fact (`cut: { fact: edition }`) and cannot declare a new fact. `edition` is canonical (X25). Any other `key-value` or `key=value` in curly braces is reported in the `tags` map of the movie, series or episode, with its key in vocabulary form, and never reaches a title or a version label. One key with two values is ambiguous (`conflicting_tag`). Square brackets and parentheses are not read this way, because `[Spider-Verse]` is a title.
- **X30 Episode words.** The words of a season and episode token are vocabularies: `season_words`, `episode_words`, `special_prefixes` and `animation_special_words` (a map from word to special kind). A word must be followed by a number. `e` is canonical, and `episode` and `ep` are in the shared base. Language packs add the other episode words, and the built-in rules contain the words of every language (X11), so `Show Staffel 2 Folge 3` reads with no configuration. An episode word of a pack or an overlay ranks below a `3x08` token, because it can be a title word (`Gomorra 3x08 Episodio 2`).
- **X31 Typed kinds.** A word only names a typed fact, and the project adds a fact by release. The artwork roles `clear_art` and `disc_art` and the extra kinds `opening` and `ending` are such facts, each with a canonical name. The public enums of facts are non-exhaustive, so a new variant does not break a caller.
- **X32 Layers and replace (owner decision).** Language packs are the first layer and user overlays the second. A user overlay can remove a word of a declared pack or give it another meaning. User overlays that disagree are still rejected (X10), and two overlays that replace one vocabulary conflict. `replace` has the shape of `add` and drops every other entry of that vocabulary, except its canonical names; it cannot appear beside `add` or `remove`. Rules always start from the built-in rules, so a caller never defines a whole vocabulary set.
- **X33 Profile template slots.** The profile's `templates` spell parts of a name with R14 templates: `work_name` (`title`, `year`), `season_folder` (`season`), `episode_file` (`reference`, `work_name`, `episode_title`), `provider_tag` (`provider`, `id`), `edition_tag` (`edition`), `version_label` (`label`) and `part` (`part`). Each slot has a closed field list and required fields; another field or a missing required field is invalid. A slot that is not listed keeps its default, and a slot takes precedence over the style option of that part. The `version_label` and `part` slots write their own separators. The target filesystem's rules apply to the rendered text. `Rules::reading_profile` also reads the literal words of the `season_folder` and `part` slots and the key of the `edition_tag` slot. `Rules::check_profile` writes one movie and one series, reads them back, and reports each fact that does not come back (`does_not_read_back`). The CLI and the server reject such a profile. Sidecar names have no slot, because S3 matches a sidecar by the video stem and `.`.
- **X34 Grammar data.** `episode_tokens` adds templates of episode tokens (`Kap {episode}`, `{season}.{episode}`). A template uses `episode` once, may use `season` once, and has no optional section. It fills only the typed `season` and `episodes`. A space in its text matches a space, `.`, `-`, `_` or nothing (X19). User regexes stay out of scope. `separators` lists the characters between words, other than the dash; the tokenizer and the display title read it. `bracket_pairs` maps an opening character to its closing character, and `【】` is a default pair. `(`, `[`, `{` and the space are canonical.

## Rendering, planning and validation

Generation is stricter than parsing. Each fact has one output spelling. These are the rules of the default output profile (owner decisions). A profile changes only the settings that it declares (provider order, target filesystem, component length).

- **R1 Movie names.** The movie folder is `Title (Year) {tmdb-N}`. The file name is the folder name plus ` {edition-X}`, ` - <version label>`, ` - partN` and the lowercase extension, in that order: `Title (Year) {tmdb-N} {edition-Director's Cut} - 2160p - part1.mkv`. The name carries one provider ID: the first one that the facts carry in the profile's order (default `tmdb`, `imdb`). A version label is written only when the movie has several versions (M10). The label carries no provider or edition tags (M10), and the edition is the version's own. Extras are placed in their kind's vocabulary folder under the movie folder (`Trailers/Theatrical Trailer.mkv`). An extra's name is its title and year (`Trailer (2013)`) and part. If an extra is in a subfolder of an extras folder and that subfolder is not itself a vocabulary folder, the extra keeps that subfolder (`Featurettes/On Location/01. Adrift.mkv`), so groups stay separate. There is one folder per kind: `Trailers`, `Behind The Scenes`, `Deleted Scenes`, `Featurettes`, `Interviews`, `Scenes`, `Shorts`, `Clips`, `Bloopers`, `Samples`, `Theme Music`, `Backdrops`, `Other`, `Extras` (data).
- **R2 TV names.** The TV layout is `Show (Year) {tvdb-N}/Season 01/Show (Year) - S01E01 - Episode Title.ext`, with ` - <version label>` and ` - partN` after the title. The provider order is `tvdb`, `tmdb`. The ID is on the series folder only. Seasons and episodes have at least two digits (`Season 00` for specials, `S01E100`). A contiguous range is written `S01E02-E03`. A non-contiguous list repeats the token (`S01E01E03`). A list is never written as a range that includes a missing episode (T15). A dated episode is written `Show (Year) - 2024-05-17 - Title.ext`. It is placed in the series folder unless the facts carry a season. Absolute numbers are never written. An absolute-only episode is blocked unless the facts also carry its season and episodes. A series extra is placed in a vocabulary folder of the series folder. A season extra is placed in a vocabulary folder of its season folder. An episode extra is placed in a vocabulary folder of its season folder and named `S01E05 - Title` (T11).
- **R3 Missing facts.** A missing optional fact (year, provider ID, edition, episode title, version label, part) is left out with its separator. If a required fact is missing, the name is blocked with a reason: `missing_title` (movie or series), `missing_extension`, `missing_season`, `missing_episode_reference`, `absolute_without_season_mapping`, `missing_extra_title`.
- **R4 Sidecar names.** A sidecar name is `<video stem>[.<title>][.<language>][.<flags>].<ext>`. The language is written as its BCP 47 tag. Flags are written in canonical order and spelled `default`, `forced`, `sdh` (S4). The extension is lowercase. A sidecar of an extra or a part uses that file's stem.
- **R5 Target filesystem.** The default target is `portable`, which is safe on Windows, macOS and Linux. On `portable`, `:` is replaced with ` -`; `/`, `\` and `|` are replaced with `-`; `"` is replaced with `'`; `<`, `>`, `?` and `*` are dropped; control characters are replaced with spaces; runs of spaces are collapsed; and trailing dots and spaces are removed from each component. A component whose part before the first dot is a reserved device name (`CON`, `PRN`, `AUX`, `NUL`, `COM1`-`COM9`, `LPT1`-`LPT9`, ignoring case) is blocked (`reserved_name`). The `posix` target only replaces `/` and drops NUL. The profile's `reserved_names` lists further names that are blocked in the same way on both targets; a profile cannot allow a device name that the target reserves. On both targets, a component longer than the profile's limit in UTF-8 bytes (default 255) is blocked (`component_too_long`). Output text is NFC (X3), so one fact has one byte spelling.
- **R6 Planning.** `plan_renames` returns proposals (old path → new path) and blocked proposals with reasons, never filesystem operations. Files that already have their target name are left out. `plan_renames` proposes renames only from settled facts. It blocks an ambiguous item (`ambiguous_identity`, `ambiguous_provider_id`, `ambiguous_parts`, `ambiguous_season`), misplaced series content (M15) and an extra that no item owns (`no_owner`). A video's parts, sidecars, stills, artwork and leftover files named after its stem move with the video (`moves_with`). The other files under a folder that contains only the video's item also move with it. When one of these files is blocked, all of them are blocked (`moves_with_blocked_file`). A proposal is blocked when its destination is equal to a file that stays (`destination_exists`), equal to another proposal's destination (`destination_collision`), or equal to a staying or proposed path, or to one of its folders, only when case (X2) or Unicode normalization (X3) is ignored (`destination_differs_only_in_case_or_normalization`). Blocking repeats until no further proposal is blocked. A rename plan never splits one series across two folders. When any file of a series (its episodes, extras, sidecars or folder files) is blocked, its series and season folders are not renamed. The series' other files are then renamed only inside their current folders, and files that already have that name are left out. This step repeats with the blocking until no further proposal changes. A file that no item claims and that moves with its folder is marked `unclaimed`, so the caller can keep or delete it. A rename that changes only case or normalization is marked `case_only`. Proposals are returned in execution order. A proposal whose destination is another proposal's source comes after that proposal. Proposals in a cycle are marked `requires_temporary_step`. The caller schedules the temporary names. An extra without a title keeps its file stem as its title.
- **R7 Validation.** `validate` reports, per rule ID, the entries involved, each with a severity. **error**, the entry cannot be named safely: `insufficient_facts` (a required fact is missing, R3), `invalid_name_under_profile` (`reserved_name`, `component_too_long`), `ambiguous_identity` (with the item's reason), `conflicting_provider_ids` (with the provider), `misplaced_series`, `missing_part`, `duplicate_part`. **warning**, the name does not follow the profile or the entries are likely wrong: `profile_violation` (a file whose name under the profile differs, with the proposed path), `folder_mismatch` and `overlapping_episodes` (R8), `clashing_version_labels` (versions of one item whose labels and editions are both equal ignoring case, absent ones included), `orphan_extra`, `orphan_sidecar` (an unclaimed subtitle or audio file), `orphan_artwork` (an unclaimed image), `unclaimed_file` (any other unclaimed file; an NFO whose name matches its item is attached, S9, so an unclaimed NFO matches no item), `missing_year` and `missing_series_year` (R9). **info**, an optional fact is missing: `missing_provider_id` and `missing_episode_title` (R9). The profile's `severity` map overrides a rule's severity, or turns the rule `off`. The `severity` map changes what is reported, never what a plan blocks. Diagnostics are sorted by their first path, then by rule, then by reason in the order that R8 lists them.
- **R8 Folder mismatches.** If a file states a fact that its folder states differently, validation reports one `folder_mismatch` per fact, with the fact as `reason`. For movies, the facts are `title`, `year` and `edition` (the `{edition-X}` tag), compared against the owning folder. For TV, the facts are `series_title` and `series_year`, compared against the series folder, and `season`, compared against the season folder. A fact that the file leaves out is not a mismatch. Titles are compared in comparison form (P4, as in M1). The diagnostic only reports the mismatch and does not change the identity. Identity still follows M1, M2, T2 and T9. So a contradiction that makes a movie ambiguous also produces `ambiguous_identity`. With an untrusted file title or a folder with a provider ID (M1), the item keeps the folder's identity, and the `profile_violation` proposes to rename the file. A file has its own series title only when T2 offers that title as the series' `alternate_identity`. The text before a single episode's code is its episode title, not a mismatch. Episode items of one series whose coverages overlap without being equal (T17) produce one `overlapping_episodes` diagnostic that lists their videos.
- **R9 Missing facts.** A name can follow the profile and still leave out an optional fact (R3). Validation reports this with one diagnostic per item, not per file: `missing_year` for a movie without a year, `missing_series_year` for a series without a year (both also when a provider ID identifies the work), `missing_provider_id` for a movie or series without a provider ID, and `missing_episode_title` for an episode without a title. The paths of a movie or episode diagnostic are all of the item's videos. The path of a series diagnostic is its folder, or its episodes' videos if it has no folder. An item that already has an error diagnostic gets none of these diagnostics. Extras never get them. Plans still propose the name without the fact.
- **R10 Category folders.** A planned path keeps the folders above an item: above a movie's or series' own folder, or above its first video if it has no folder (`Collections/Saga/Film (2001)/` stays in `Collections/Saga/`, and `Kids/Show/` stays in `Kids/`). R1 and R2 give the name below those folders. Category folders are the caller's organisation (T1, 4.3), and a rename plan changes names, not that organisation. Two works in different category folders do not collide. A movie states the folder that contains its folder, or its video if it has no folder, as its `collection`, unless that folder is another movie's folder.
- **R11 Duplicates.** Movies, and series, that are one work in two folders are `duplicate_work` (warning), listing a movie's first video or a series' folder per work: the same resolved provider ID (reason: the provider), else the same title in comparison form (P4) and the same year (reason `title_and_year`). Versions of one movie are one work and never a duplicate (M10); merging is the caller's. Episode items of one series with the same season and the same episodes in the aired order are `duplicate_episode` (warning, reason `SxxEyy`), listing their videos; coverages that overlap without being equal stay `overlapping_episodes` (R8). With a reference list (X18), a listed episode that the library lacks is `missing_episode` and an episode that the list lacks is `unexpected_episode`; specials are listed and compared as season 0.
- **R12 Coverage.** The profile declares what a library needs; validation reports what is missing. `required_assets` maps an item kind (`movie`, `series`, `season`, `episode`) to roles: an artwork role (S7), `nfo` (S8, S9), `theme_song` or `theme_video` (an extra of that kind). Each role that an item lacks is `missing_asset` (warning, reason: the role), on the movie's or series' folder, the season folder (or the series folder without one), or the episode's first video. `wanted_subtitles` lists languages with optional flags. Each feature video, the first file of each version, without an external subtitle of that language that has those flags is `missing_subtitle` (warning, reason: the language and flags, `en.forced`). A base language accepts its regions (`pt` accepts `pt-BR`), not the reverse. Embedded tracks are not counted, because probing is the caller's. A required NFO is present if the item has one or any of its versions has one, because an item's own NFO is only its primary version's (S9).
- **R13 Reporting.** Every rule has a stable code, grouped by its first digit: `N1xx` identity, `N2xx` parts and versions, `N3xx` files that no item claims, `N4xx` names under the profile, `N5xx` missing facts and assets, `N6xx` the reference. A code never changes meaning; a new rule takes a new code. Each diagnostic carries its English message, rendered from a template per rule, or per rule and reason, in the data file `data/messages/en.yaml`. The profile's `suppressions` leave out the diagnostics of a rule, or of every rule, with a path that a gitignore-style glob matches. The `summary` counts the diagnostics per severity and per rule and severity, and counts the suppressed ones; it is never a score. A rename plan lists release junk (X22) as `removals` instead of moving it; the caller decides whether to remove the files.
- **R14 Templates.** A template is text with fields (`{title}`, `{season:00}` padded with zeros), optional sections (`[ ({year})]`, left out if a field in them has no value) and the escapes `{{`, `}}`, `[[`, `]]`; `/` separates folders. Rendering fills the fields; a field outside an optional section without a value renders no name and is reported. A template with two fields that touch is invalid, because the reader could not separate them. The reader reads what a template writes through the vocabularies and episode tokens of the rules (X33, X34), not through the template.
- **R15 Output profile options.** Every option defaults to the R1-R5 layout. `movie_layout: flat` writes a movie's files at the root or in its category folder; a movie that has extras, artwork or a folder NFO keeps its folder, because those files need a folder to stay with the movie, and the unclaimed files of a flat movie's folder are not moved. `season_folder_style` is `padded` (`Season 01`) or `unpadded` (`Season 1`). `specials_folder` replaces the season 0 folder name; the caller sets it in the library's language. `extras_folders` replaces the folder of each listed extra kind. `provider_tag_style` is `braces` (`{tmdb-1}`), `brackets_id` (`[tmdbid-1]`) or `none`; an edition is always written as `{edition-X}`. `character_replacements` applies to fact text before the filesystem rules, so a caller can drop a `:` that the portable target would write as ` -`; at each position the longest listed text is replaced. `version_label_style` is `dash` (` - 2160p`) or `brackets` (` [2160p]`); a part is always ` - partN`. `extension_case` is `lower` or `keep`.
- **R16 Rename scripts.** `nomenclator plan --script sh|ps1` prints a script that performs the proposals, and `--undo-script FILE` writes the script that reverses them. The script changes to the library's absolute path and moves files by root-relative paths. Every proposal in a rename cycle, and every proposal that changes only letter case, first moves to `<source>.nomenclator-N.tmp`; all temporary moves run before the final moves, so each source of a cycle is free, and a case-insensitive filesystem renames a case-only change. Each move creates the destination folder and stops the script if the destination exists. The reverse script moves each destination back to its source in reverse order, which keeps the plan's ordering constraint. Scripts remove no file or folder: proposed removals are comments, and emptied folders stay.
- **R17 Import.** `plan_import` takes the interpretation of a download folder, the interpretation of the library and the library's entries, and proposes moves from download-relative paths to library-relative paths. The download's category folders are not kept, because they describe the download client, not the library. A download work matches a library work if the library type and the title comparison key (P4) are equal, the years are equal or one is missing, and no provider has two different IDs; if some matches have the same year, only those count. A single match fills the missing year and provider IDs and puts the files in the library work's existing folder, even if that folder does not follow the profile. Several matches block the work's files with `ambiguous_library_work`. A destination that is a library file is blocked with `destination_exists`, so an import never replaces a file; a new version of a work in the library is reported this way. Samples, release junk and unclaimed files that follow no video stay in the download and are listed with their reason. An import has no rename cycles, so its proposals are sorted by source path. `nomenclator import <download> <library>` prints the plan, and `--script` and `--undo-script` write scripts with a source and a target root (R16).
- **R18 Layout conversion.** `plan_conversion` interprets a library that the `from` profile wrote and plans it under the `to` profile as one rename plan, so cycles and collisions between old and new names are handled once (R6). The interpreter already reads every spelling that a profile option writes, except the names that a profile chooses itself: its extras folder names and its specials folder name. `Rules::reading_profile` adds those names to the extras and specials vocabularies, and the rules identity lists them as an overlay named `profile`. A name that is in a rival vocabulary rejects the profile with the overlay diagnostics. Character replacements are not reversed, because they lose information; a converted name keeps the replaced text. `nomenclator plan --from-profile old.yaml --profile new.yaml` prints the conversion.
- **R19 Asset names.** `NamingFacts.asset` renders the name of an NFO, artwork or theme file for the item that the facts describe: an episode if they have episodes, a date or absolute numbers, else a season if they have a season, else the movie or series. A movie's, series' or season's asset is in its folder under a generic name, and an episode's asset follows the episode's stem, because the reader attaches those names (S6, S8, S9). Each artwork role is written in the spelling that the most readers read: `poster`, `fanart`, `banner`, `clearlogo`, `landscape`; an episode's still and thumb are `<stem>-thumb`, and its other artwork is `<stem>-<role>`. NFOs are `movie.nfo`, `tvshow.nfo`, `season.nfo` and `<episode stem>.nfo`. A theme song is `theme.<ext>` and a theme video is `theme.<ext>` in the theme video folder (R1, R15), for a movie or series only. A role that the item kind cannot have is blocked with `asset_role_not_for_item`. A movie with an asset keeps its folder in a flat layout (R15). Rename planning keeps the names of existing assets: it moves them with their folder or video (R6) and does not rename `folder.jpg` to `poster.jpg`, so a caller's files are never merged into one name.

## Provider matching

`rank_candidates` scores candidates that the caller fetched. It has no knowledge of any provider's API. These weights are this project's own, and the cases in `corpus/matching/` fix them.

- **P1 Scores.** A score is the sum of named components, each with its points and reason. A score is not a probability. Every candidate is returned with its breakdown and contradictions. Uncontradicted candidates come first, then candidates are ordered by score, then by caller handle. The supplied order never affects the result. Two candidates with the same handle are invalid input (`duplicate_handle`).
- **P2 Hard contradictions.** A candidate is never selected, however well its title agrees, when it carries a different ID in a namespace the facts carry (`different_id`), is of another kind than the facts' known kind (`different_kind`), has a year more than 1 from the facts' year (`year_beyond_tolerance`; a date's year counts when no year is given), has episode coordinates that the facts' explicit ones exclude (`different_episode`: the number is not among the facts' episodes, or both seasons are known and differ), or, for an episode, has an air date other than the facts' air date (`different_date`). A field that is missing on either side adds no points and is not a contradiction.
- **P3 Provider IDs.** An equal ID in a shared namespace scores 100 and decides the selection. When any candidate carries one of the facts' IDs, only such candidates can be selected. If one of them is uncontradicted, the result is `selected` (`provider_id`). If several are uncontradicted, the result is `ambiguous` (`several_provider_id_matches`). If each of them is contradicted, the result is `no_match` (`provider_id_match_contradicted`), and the matcher never falls back to titles. IDs in other namespaces are not compared.
- **P4 Titles.** The best agreement between any of the facts' titles (title and alternates) and any of the candidate's titles (primary and alternates) counts once. Titles are compared in their comparison form. The comparison form is used only for matching and title agreement (M1), never for displayed titles. The comparison form applies NFC and case folding, spells out ligatures, strips accents (NFD without combining marks), drops punctuation and separators, drops a leading article when more words follow (`the`, `a`, `an` and common equivalents such as `le`, `la`, `les`, `der`, `die`, `das`, `el`, `il`, as data), and reads a whole-word Roman numeral I-XX or spelled number one-twenty as its digits. Titles with equal comparison keys (the words joined) score 60 (`exact_title`). Otherwise the titles' word sets in the same form score 50 × their Dice agreement (2 × shared words ÷ all words), rounded, when at least half agree (`similar_title`). Below that they score 0 (`dissimilar_title`). So `The Northern Passage` equals `Northern Passage`, `Part II` equals `Part 2` and `Part Two`, and `Βόρειο` equals `ΒΟΡΕΙΟ`. An article inside a title and a numeral inside a word (`Vivid`) stay as written. The folds produce rare false agreements (`Die Hard` against a title `Hard`). These are accepted in exchange for the common correct agreements. The candidate title that agreed is returned.
- **P5 Other evidence.** The same year scores 20, and a year 1 apart scores 10. For episode coordinates, the same season and episode scores 60 (`same_episode`), and the same episode with a season unknown on one side scores 30. The same air date of an episode scores 60. A multi-episode file agrees with each episode it covers, so the episodes tie. Callers rank one episode reference at a time.
- **P6 Selection.** Without an ID match (P3), the best uncontradicted candidate needs at least 60 points: an exact title alone, a similar title with the same year, or matching coordinates or date. Below that the result is `no_match` (`insufficient_evidence`), even for a single candidate. If any other uncontradicted candidate is within 10 points of the best, the result is `ambiguous` (`tied_scores`, listing them). Otherwise the best candidate is `selected` (`best_score`). With no candidates, the result is `no_match` (`no_candidates`). With only contradicted candidates, the result is `no_match` (`all_contradicted`).
- **P7 Search queries.** `search_queries` returns the queries that a caller sends to a provider, most specific first: a lookup per provider ID (in namespace order), the title with the year, each alternate title with the year, the title without the year, each alternate title without the year, and the main title with the year. The year is the facts' year, else their date's year. The queries without a year cover a provider whose year differs by more than the facts allow. The main title is the text before the last `: ` or ` - ` of the title (`Mission: Impossible` of `Mission: Impossible - Dead Reckoning`), because a provider often lists a subtitle differently. A query whose title has the comparison key (P4) and year of an earlier query is left out. Titles are sent as the facts give them, with whitespace collapsed; titles from an interpretation contain no release words (M-decisions), so the queries do not parse them again. Facts without a title or provider ID give no queries. `match_facts` builds the facts of each interpreted movie, series and episode: an episode's title is its episode title, and an episode in the absolute order carries its absolute numbers.
- **P8 Richer candidates.** A candidate can carry an `original_title`, `localized_titles` with a language, `release_dates` with a country, and `coordinates` in other episode orders. Its titles are compared in the order primary, original, alternate, localized, and the title component states the matched title and, for a localized title, its language. Each year counts: the candidate's year (else its date's year) and each release date's year. The closest year agrees, and the year component states the release date and country that agreed. The candidate contradicts the facts' year only if every year is beyond the tolerance, because a festival release and a later theatrical release are one work. Facts can state the `order` of their coordinates (X17). In the aired order or with no order, the candidate's `season` and `episode` are compared; in another order, the candidate's coordinates in that order. A candidate without coordinates in that order is not compared by coordinates. An absolute number is a whole coordinate, so it scores `same_episode` without a season. The episode component states the order if the facts state one.
- **P9 Batch ranking.** `rank_batch` ranks many queries, each a handle with its facts and candidates, in one call. The results are sorted by handle, so the order of the queries never affects them. Queries that share a handle are invalid input (`duplicate_query_handle`), and the other queries are ranked. `RankCandidates` on the wire is a batch with these rules.
